## Coverage and bottlenecks

The test files cover one-room quote/invoice examples, empty inputs, key shape, and a legacy cancellation boundary ([tests](../../starter/booking_platform/tests/test_quote.py#L4-L10), [invoice test](../../starter/booking_platform/tests/test_invoice.py#L4-L8), [baseline](../../starter/booking_platform/tests/test_baseline_contracts.py#L5-L10), [rules test](../../starter/booking_platform/tests/test_rules.py#L4-L7)). There are no in-repo tests for multiple lines, explicit room count, aggregate rounding edge, negative/invalid values, one-shot iterators, `pricing.cancellation_fee`, or 48-hour local-time policy. “Weak coverage” is based on inspected test cases; no coverage tool was run.

No third-party or versioned dependency is declared, so deprecated library risk cannot be assessed. The main architectural bottleneck is duplicated fee/subtotal business logic, with `api.create_quote` tightly dependent on pricing dictionary keys. No process, database, or network single point of failure can be identified from this repository. The application has no deployed-system evidence.
